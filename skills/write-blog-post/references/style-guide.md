# House Style, Content, and Grammar

Default house rules. A project's voice profile can override any of these; note overrides there, not by editing this file.

## Punctuation

1. **Don't overuse exclamation marks.** One per post is plenty. Zero is fine.
2. **No em-dashes (—).** Use separate sentences for clarity. For a run-on thought where an em-dash would traditionally go, use an ellipsis, parentheses, or a comma.
3. **Links close before punctuation.** This is an [example](#) of how to do it. The period sits outside the link.
4. **Double quotes for highlighted terms.** Click the "Add New" button, not the 'Add New' button.

## Contractions

Use editorial judgment:

- **Formal or technical documentation:** consider expanding. "We would" is faster to parse than "we'd," especially for readers who aren't native English speakers.
- **Conversational blog prose, storytelling, and CTAs:** keep contractions. "Customers don't stay because of a feature list" reads more naturally than the expanded form.

Don't mechanically expand every contraction in an editing pass.

## Names and Terms

1. **Use official names.** Products, features, plugins, and companies are written exactly as their own docs or README write them. Don't invent a name ("the Events tool") for something that has a real one.
2. **Full name first, then abbreviate.** Write out the full name on first use, then switch to the short form ("Content Management System (CMS)," then "CMS"). Never use an unofficial abbreviation.
3. **Consistent casing.** If the brand writes a term a particular way (e.g., "WordPress," "GitHub," "iPhone"), match it every time. Put project-specific casing rules in the voice profile.
4. **Spelling and tech terms:** follow `oreilly-word-list.md`, then Merriam-Webster Collegiate for anything not covered.

## Titles and Headings

1. **Title Case for titles and headings that are not sentences.** No punctuation on those headings. (A title-capitalization tool set to NY Times style is a good reference.)
2. **Sentence case when a heading is a complete sentence**, declarative, question, or imperative. Punctuation is fine there ("Can I use this with my existing theme?").
3. **Never put punctuation in a post title** unless it's a question.
4. Headings double as table-of-contents entries. Write ones that make sense out of context.

| Heading | Case | Why |
|---|---|---|
| `Why Free Content Works` | Title | Label, not a sentence |
| `How to Set Up a Free Tier` | Title | Label |
| `Can I use this with WooCommerce?` | Sentence | Complete question |
| `Your customers deserve a faster checkout.` | Sentence | Complete declarative sentence |

When in doubt: if it reads like a section label, Title Case. If it reads like a sentence you'd say out loud, sentence case.

## Dates

- Internal notes: `YYYY/MM/DD`.
- Reader-facing: write it out. "October 25th, 2025."

## Settings, Fields, and UI Paths

**Field or setting descriptions** use bold Title Case term, colon, description. The space sits outside the bold:

`**Renewal Date**: The date the next payment runs.`

Not `**Renewal date** - the date…` or `**Renewal Date:**the date…`.

**Menu paths and breadcrumbs:** bold each segment separately. The `>` separator stays outside the bold.

- ✅ `**Settings** > **Payments** > **Gateway**`
- ❌ `**Settings > Payments > Gateway**`
- ❌ `**Settings** **>** **Payments**`

## Personal vs. Company Posts

Decide which one you're writing before you start. Put it in the brief.

**Personal posts** (one named author's perspective, blog or LinkedIn):
- **Drafting:** start with an outline (headings and bullets) so structure is easy to review.
- **Polish:** convert the outline into natural, conversational prose. Remove formal headings in favor of paragraph breaks, turn bullet lists into flowing sentences, and use a **bolded sentence on its own line** to highlight a key idea instead of a heading. First person, sounds like the author talking.

**Company posts** (from the business or team):
- Headings and subheadings for organization.
- Bulleted and numbered lists are welcome.
- More formal, professional tone. "We" or third person.
